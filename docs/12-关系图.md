# 关系图

共 306 条边。

## 为什么需要这张表

画家、名画、签名卡各自的字段只能记「自己是什么」，记不住「和谁有关系」。
而提示词组合真正吃的就是关系：

- **创作者 → 作品 → 材料 → 机构** 回答「这句话从哪来、能不能商用」
- **流派 → 画家 → 技法** 回答「为什么这两个人能融」
- **签名卡 → 派生自 → 母版** 回答「这张卡是为谁做的、改坏了找谁」

边的写法刻意模仿 CIDOC CRM：谁、做了什么、对象是谁，分成独立字段而不是一句话。
因为一句话没法反向索引。

## 边的类型

| 类型 | 方向 | 条数 | 强度 |
| --- | --- | --- | --- |
| `held_by` 作品 → 收藏机构 | 94 | 事实 |
| `uses` 作品 → 承载材料 | 104 | 事实 |
| `student_of` 画家 → 画家（师承） | 7 | 强，可照搬 |
| `influenced` 画家 → 画家（影响） | 45 | 弱，只能借鉴 |
| `derived_from` 签名卡 → 母版 | 3 | 事实 |
| `serves` 卡片 → 任务 | 21 | 推荐关系 |
| `realizes` 签名卡 → 原子模块 | 12 | 构成关系 |
| `aligned_with` 实体 → 外部标准 | 20 | 映射声明 |

**师承与影响必须分开。** 师承可以照搬，影响只能借鉴——
两者混在一张表里，就会在融合提示词时把「借鉴」当成「传承」来用。

**关于边的编码**：每条边都有 `R-001` ~ `R-306` 的全局连续编码，
逐条对照见 `dist/relations.json`。这里不逐条列出 —— 306 行编码会让这张表没法读，
而这张表要解决的是「有哪些关系、强度如何」，不是「每条叫什么」。
