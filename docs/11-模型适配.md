# 模型适配与验证

共 12 条。这一层存在的理由只有一个：**同一段提示词在不同模型上行为差别极大。**

括号权重在 SD 系有效、在 Flux 上基本被忽略；负面提示在 MJ 上要换另一种语法；
CFG 与步数的可用区间在几代模型之间整体下移。把这些记成「模型实测」，
才不会拿 SD 的经验去调 Flux，然后怀疑是自己词写得不对。

**这一层的所有结论都只在对应模型上成立。** 换模型请先查 `tests` 表，不要直接沿用。

## 家族：classic（1 条）

### Stable Diffusion 1.5 / 2.x · `MT-01` · 编码 `MT-001` · `tested` 已测试

| 项 | 值 |
| --- | --- |
| 年代 | 2022-2023 |
| 权重语法 | `(tag:1.3)` |
| 权重可用区间 | 1.1 – 1.4 |
| 引导值 | 7（可用 5 – 8） |
| 步数 | 25 – 40 |
| 采样器 | DPM++ 2M Karras 一类收敛快的采样器最省算力 |
| 提示词形态 | 短标签串，用逗号分隔，不写句子 |
| 建议长度 | 50 – 120 词 |
| 负面提示 | 支持，且效果显著 |
| 自然语言正文 | 弱，不擅长长句 |

- **权重实际效果**：强，注意力集中明显
- **括号叠加**：(词) 约等于 1.1 倍，嵌套相乘，三层约 1.33 倍

**事实**：经典扩散模型，CLIP 文本编码器，注意力对括号权重响应最强。

**观察**：标签顺序影响很大，靠前的词拿到更多注意力。

**实测**：权重 1.1 到 1.4 是甜区；超过 1.5 期待色带、解剖崩坏与概念串味。

**注意**：这一代的经验最丰富，但它已经是最旧的架构，本库的建议配置以 SDXL 为基线。

**已知失败类型**

- 权重堆到 1.7 以上出现色带与解剖崩坏

### SDXL 1.0 · `MT-02` · 编码 `MT-002` · `tested` 已测试

| 项 | 值 |
| --- | --- |
| 年代 | 2023- |
| 权重语法 | `(tag:1.3)` |
| 权重可用区间 | 1.1 – 1.4 |
| 引导值 | 7（可用 5 – 8） |
| 步数 | 30 – 45 |
| 采样器 | DPM++ 2M SDE Karras |
| 提示词形态 | 标签加短词组，句子不要超过两个分句 |
| 建议长度 | 75 – 150 词 |
| 负面提示 | 支持，推荐使用 |
| 自然语言正文 | 中等，短标签串最稳 |

- **权重实际效果**：中等，仍然有效
- **括号叠加**：(词) 约 1.1 倍，(tag:1.3) 为显式写法；方括号是减弱的旧写法

**事实**：双文本编码器，1024 像素原生训练，画质与提示词响应都显著好于前代。

**观察**：对负面的响应依然稳定，可以放心用来压解剖问题。

**实测**：1.0 基线原则：先用无权重版本跑一遍，如果每个元素都出来了就不要加权重。已经能出对的提示词，再加权通常会更差。

**注意**：要拆解概念就用 BREAK 类节点或 ComfyUI 的条件拼接节点切块，比硬调权重更可控。

**已知失败类型**

- 高纯度补色配高权重会溢出
- 把权重误当质量开关会牺牲画面

### ComfyUI（SDXL 系） · `MT-07` · 编码 `MT-007` · `tested` 已测试

| 项 | 值 |
| --- | --- |
| 年代 | 2023- |
| 权重语法 | `(tag:1.3) + 区域提示` |
| 权重可用区间 | 1.1 – 1.4 |
| 引导值 | 7（可用 5 – 8） |
| 步数 | 30 – 45 |
| 采样器 | DPM++ 2M SDE Karras |
| 提示词形态 | 原生条件节点，分区域分别送入文本 |
| 负面提示 | 支持 |
| 自然语言正文 | 中等 |

- **权重实际效果**：强，且可按区域分配
- **括号叠加**：支持

**事实**：节点式工作流，能把不同的提示词分别送进同一张图的不同区域。

**观察**：区域提示与注意力耦合在控制空间位置这件事上，远胜于文字权重。

**实测**：要控制物体出现在画面哪里，优先用区域提示或注意力耦合节点，而不是把文字权重调高。

**注意**：本库 AM 类模块里标了 role 为 region 的条目，正是为这个场景准备的：它们本就该只作用于一块地方。

**已知失败类型**

- 区域提示的边界遮罩没对齐会出现接缝

### Flux.1 dev · `MT-04` · 编码 `MT-004` · `tested` 已测试

| 项 | 值 |
| --- | --- |
| 年代 | 2024- |
| 权重语法 | `基本忽略` |
| 权重可用区间 | 1 – 1 |
| 引导值 | 3.5（可用 2.5 – 4.5） |
| 步数 | 25 – 35 |
| 采样器 | 默认流匹配采样器，不要换回扩散采样器 |
| 提示词形态 | 一到四句自然语言，把重点写进句子而不是括号 |
| 建议长度 | 1 – 4 词 |
| 负面提示 | 支持但不是必需，很多情况下不写更好 |
| 自然语言正文 | 很强，整段自然语言都读得进去 |

- **权重实际效果**：几乎无效，括号里的数字可能当成画面文字
- **括号叠加**：不要用

**事实**：流匹配架构，配自然语言理解力很强的文本编码器。

**观察**：它按整句理解语义，所以句子写得越完整，响应越好。

**实测**：引导值 3.5 是标准值，可用区间 2.5 到 4.5。想强调某个概念，正确做法是改写句子（明确说出颜色、材质、重要性），而不是加括号。

**注意**：本库加 flux 平台方言时用的策略：权重词就地重复一遍描述，最重要的概念挪到句首，不输出任何括号。

**已知失败类型**

- 沿用括号权重会产生字面数字被画进画面
- 照抄 SD 的负面词清单会过度压制

| 权重语法 | `tag::2` |
| 权重可用区间 | 0.5 – 2 |
| 引导值 | — |
| 步数 | — |
| 采样器 | 内置 |
| 提示词形态 | 描述性短语，开头写媒介（如图注明写插画） |

**已知失败类型**

- 权重超过 2 后结果迅速失控
- 把负权重当负面提示用会得到反效果

### ControlNet / IP-Adapter · `MT-08` · 编码 `MT-008` · `tested` 已测试

| 项 | 值 |
| --- | --- |
| 年代 | 2023- |
| 权重语法 | `由底层模型决定` |
| 权重可用区间 | 0.4 – 0.7 |
| 引导值 | — |
| 步数 | — |
| 采样器 | 随底层模型 |
| 提示词形态 | 提示词只负责补氛围与细节，结构交给控制通道 |
| 负面提示 | 随底层模型 |
| 自然语言正文 | 随底层模型 |

- **权重实际效果**：结构参考取 0.6 左右稳定；风格参考可到 0.8
- **括号叠加**：随底层模型

**事实**：控制通道按输入约束生成：骨架图定姿态、深度图定空间、边缘图定轮廓；适配器则喂参考图定风格。

**观察**：两者性质不同：控制通道管结构，适配器管风格，混用会互相干扰。

**实测**：适配器权重 0.4 到 0.7 最常用；控制通道的结构权重超过 0.9 会把画面锁死到参考图，失去变化空间。

**注意**：这是解决本库 T-06 区域改造任务的正解：用遮罩控制通道，只在目标区域施加，不要靠提示词。

**已知失败类型**

- 结构权重给太高会连原图的姿态一起僵化复制
- 用风格参考时若不给风格词，会退化成内容参考

### GPT 图像 / Ideogram / Firefly 等自然语言模型 · `MT-10` · 编码 `MT-010` · `tested` 已测试

| 项 | 值 |
| --- | --- |
| 年代 | 2024- |
| 权重语法 | `忽略` |
| 权重可用区间 | 1 – 1 |
| 引导值 | — |
| 步数 | — |
| 采样器 | 内置 |
| 提示词形态 | 完整句子，明确写出重点与优先级 |
| 负面提示 | 多数不提供，或效果有限 |
| 自然语言正文 | 很强，整段对话式描述都有效 |

- **权重实际效果**：无，强调靠位置与重复
- **括号叠加**：不要用

**事实**：这类模型不解析数值权重，强调靠语义位置：越靠前、重复越多，被关注得越多。

**观察**：写「一身鲜红的红毛狐狸」比写「红狐狸」有效；写「红衣是画面主色」比任何权重语法都有效。

**实测**：有效顺序是：先写主体，再写次要元素，用具体形容词替代强度词。这是本库 gpt 输出通道的设计依据。

**注意**：本库 gpt 通道输出的就是完整自然语言，直接可粘，不要再自己补括号。

**已知失败类型**

- 堆砌括号权重
- 把最重要的词放在最后
