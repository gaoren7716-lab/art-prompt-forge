# 任务模板与原子模块

这一篇是第三层与第四层：使用者带着诉求来，引擎把诉求拆成可填的槽位。

## 一、任务模板（13 个）

以前签名卡按「题材 + 画家」分类，但使用者真正的入口是「我要做一张海报」或
「我要把这段改成油画」，不是「我要一张风景」。按任务组织，才对得上实际工作流。

每个任务给四样东西：

- `ask` 使用者通常怎么开口（原始诉求）
- `slots` 这类任务必须填满的槽位，缺一个就出不了好图
- `default` 建议的起始配方
- `check` 出图后必须自己看一眼的地方（验收清单）

### 直接复现（1 个）

心里已有一张图或一位画家，要一张能直接用的成品

#### 一键成品 · `T-01` · 编码 `TK-001` · `tested` 已测试

> 用户会这么说：**给我一张梵高风格的向日葵**

**要达到什么**：不填任何参数，点一下就得到一段能用的提示词

**必填槽位**：`painter` / `subject`

**建议起始配方**

```json
{
  "subjects": [
    "S-12"
  ],
  "painters": [
    "P-NE06"
  ],
  "strength": 1,
  "platform": "sd"
}
```

**出图后必须自己看一眼**

- [ ] 画面里有没有出现不该有的现代物件
- [ ] 笔法是否可辨，而不是只有色调像

**为什么容易做砸**：这条路最省事，但也是最容易出问题的：模型很容易只学到画家的色调，把笔法丢掉。

**怎么做**：先看 FORGE.ready(pid) 的输出，确认七面都进去了；如果只有色彩在，优先检查该画家的 tags 是否带了冲突标签被误静音。

**可用的现成卡片**：`G-01` `G-07` `G-12`

### 风格借用（1 个）

要某位画家的感觉，但题材是自己的

#### 换题材借风格 · `T-02` · 编码 `TK-002` · `tested` 已测试

> 用户会这么说：**用莫兰迪的灰调画我家的猫**

**要达到什么**：保留某位画家的色彩与气质关系，题材完全替换

**必填槽位**：`painter` / `subject` / `motif`

**建议起始配方**

```json
{
  "subjects": [
    "S-18"
  ],
  "painters": [
    {
      "id": "P-IT11",
      "w": 1
    }
  ],
  "strength": 0.9,
  "platform": "sd"
}
```

**出图后必须自己看一眼**

- [ ] 新题材的固有色有没有被画家的旧题材色压掉
- [ ] 画家的母题有没有偷偷跟进来

**为什么容易做砸**：风格绑定的是七面整体，而题材往往也带自己的色彩与母题，两边会打架。

**怎么做**：用 OP-D 类算子只取 color 与 spirit 两面，其余静音，题材色就压不过来了。

**可用的现成卡片**：`G-07` `G-18`

### 定向变形（2 个）

把已有画面整体换成另一个年代或媒介

#### 整体时代迁移 · `T-03` · 编码 `TK-003` · `tested` 已测试

> 用户会这么说：**把这个题材改成宋代山水的感觉**

**要达到什么**：保留笔法与色彩，把媒介与空间换到另一个年代

**必填槽位**：`operator-era` / `subject`

**建议起始配方**

```json
{
  "subjects": [
    "S-12"
  ],
  "operators": [
    "OP-E-04"
  ],
  "strength": 1,
  "platform": "sd"
}
```

**出图后必须自己看一眼**

- [ ] 年代痕迹是否到位（纸绢、印章、装裱）
- [ ] 有没有混进另一个年代的东西

**为什么容易做砸**：迁移类算子内部已写好 preserve 与 forbid，但如果你自己又挂了别的年代算子，两者的 forbid 会互相打架。

**怎么做**：一次只挂一个时代迁移算子。需要叠加就先后出两版再选，不要混在一个 spec 里。

**可用的现成卡片**：`G-15` `G-21`

#### 媒介重铸 · `T-04` · 编码 `TK-004` · `tested` 已测试

> 用户会这么说：**把油画改成湿壁画**

**要达到什么**：把画面承载的物质整体换掉，构图与题材不动

**必填槽位**：`operator-medium` / `painter`

**建议起始配方**

```json
{
  "subjects": [
    "S-12"
  ],
  "painters": [
    "P-IT01"
  ],
  "operators": [
    "OP-M-01"
  ],
  "strength": 1.1,
  "platform": "sd"
}
```

**出图后必须自己看一眼**

- [ ] 原媒介的痕迹有没有残留（画布纹、笔毛痕）
- [ ] 新媒介的典型特征在不在（盐霜、接缝）

**为什么容易做砸**：媒介迁移必须同时做减法与加法：只加新媒介词不够，旧媒介词还在就会互相污染。

**怎么做**：算子的 neg 字段已经写好了要去掉的旧痕迹，别手动再补一遍负面词，重复堆负面词反而会拉低画面。

**可用的现成卡片**：`G-16`

### 局部改造（2 个）

只改某几个面，其余必须原封不动

#### 只取某一面 · `T-05` · 编码 `TK-005` · `tested` 已测试

> 用户会这么说：**只借莫兰迪的灰调，其他都别要**

**要达到什么**：从某位画家身上摘出一个零件，其余全面静音

**必填槽位**：`operator-decon` / `painter`

**建议起始配方**

```json
{
  "subjects": [
    "S-18"
  ],
  "painters": [
    "P-IT11"
  ],
  "operators": [
    "OP-D-02"
  ],
  "strength": 0.8,
  "platform": "sd"
}
```

**出图后必须自己看一眼**

- [ ] 出来的画面是否确实只剩一种倾向
- [ ] 是否因为信息太少而变成平庸的通用图

**为什么容易做砸**：只取一面时容易丢掉全部个性，因为个性往往藏在被静音的那些面里。

**怎么做**：取一面之后，至少再加一个光学模块（AM 类）补细节，否则画面会很空。

**可用的现成卡片**：`G-20`

**要达到什么**：只改画面某一块，其余保持原状

**建议起始配方**

```json

    "AM-201"
```

- [ ] 被改的区域与未改区域的光是否接得上
- [ ] 交界处有没有明显的缝

**为什么容易做砸**：分区改动在单张出图里很难做干净，因为模型没有分区输入的通道。

**怎么做**：优先用图生图加遮罩做分区，而不是靠提示词。若必须纯文本，把强度压到 0.6 以下并只加局部模块。

### 多源融合（1 个）

两三位画家的语言捏在一起，各占一部分

#### 双画家融合 · `T-07` · 编码 `TK-007` · `tested` 已测试

> 用户会这么说：**用梵高的笔法配莫兰迪的颜色**

**要达到什么**：两位画家各出一个面，角色分明

**必填槽位**：`painter-lead` / `painter-support`

**建议起始配方**

```json
{
  "subjects": [
    "S-12"
  ],
  "painters": [
    {
      "id": "P-NE06",
      "w": 1.1
    },
    {
      "id": "P-IT11",
      "w": 0.7
    }
  ],
  "strength": 1.1,
  "platform": "sd"
}
```

**出图后必须自己看一眼**

- [ ] 两位画家的痕迹是不是都能认出来
- [ ] 有没有变成四不像的中间态

**为什么容易做砸**：融合失败通常不是权重配错，而是两位的语义标签正好互斥，被冲突规则静音了一方。

**怎么做**：打开变更清单看谁被静音了。如果被静音的是你想要的那位，把它的权重提到 1.3 以上重试。

**可用的现成卡片**：`G-23`

### 系列延展（1 个）

同一套语言做一组，得保证组内一致

#### 系列延展 · `T-08` · 编码 `TK-008` · `written` 已编写

> 用户会这么说：**用这套风格做一组四张**

**要达到什么**：同一套语言做多张，组内必须像同一个人画的

**必填槽位**：`painter` / `signature`

**建议起始配方**

```json
{
  "painters": [
    "P-CN11"
  ],
  "strength": 1,
  "platform": "sd"
}
```

**出图后必须自己看一眼**

- [ ] 组内各张的色彩关系是否一致
- [ ] 母题是否同源（不能一张山水一张静物）

**为什么容易做砸**：系列最容易出的问题是每张只保住了色调，七面各张漂移。

**怎么做**：固定一份 spec 只改 subjects 与 atoms，不要每张重调权重。打包码 AFX1 就是为这件事准备的。

### 对照实验（1 个）

同时跑几个版本，用来比较哪种更好

#### 对照实验 · `T-09` · 编码 `TK-009` · `written` 已编写

> 用户会这么说：**同一张图跑三个版本，选最好的**

**要达到什么**：只改一个变量，看差别在哪

**必填槽位**：`one-variable`

**建议起始配方**

```json
{
  "subjects": [
    "S-01"
  ],
  "painters": [
    "P-NE14"
  ],
  "strength": 1,
  "platform": "sd"
}
```

**出图后必须自己看一眼**

- [ ] 三版之间是否真的只差一个变量
- [ ] 差别是否肉眼可见

**为什么容易做砸**：一次改两个变量就分不清是谁的作用，这一步没做，对照实验就白做。

**怎么做**：只动强度、平台、或者某一个算子，其余全部锁死。导出时把每版的 spec 一起存下来。

## 二、原子视觉模块（126 条 / 12 类）

比光学词条更细的一层：每个模块是**一个可独立取用的视觉单元**，带角色、带投放面。

### 角色不是可选项

不是所有模块都该同等说话。四种角色的区别在于**权重能不能压过别人**：

| 角色 | 中文 | 默认权重 | 引擎行为 |
| --- | --- | --- | --- |
| `lead` | 主导 | 1 | 按 slot 投进对应的面 |
| `support` | 辅助 | 0.7 | 按 slot 投进对应的面 |
| `region` | 局部 | 0.6 | 归集待遮罩落实，不直接进任何一面 |
| `guard` | 约束 | 1 | 强制进负面词，权重对它无效 |

**约束类（`guard`）永远压不掉。** 它不是「权重高一点的建议」，是硬边界。

**局部类（`region`）不给遮罩就等于没生效。** 引擎只把它归集到返回值的 `regionAtoms``，
并在界面上提示需要用遮罩落实。这类模块在 `modules-d.js` 里集中定义，并且成对出现——
一条给主体区、一条给背景区，各自的 `region.pairWith` 指向对方。

角色分布：主导 36 · 辅助 69 · 局部 14 · 约束 7

### 1 · 光影（13 条）

光从哪来、怎么落、暗部怎么处理 · 默认投放面 `light`（光的处理）

| 编号 | 编码 | 词条 | 角色 | 状态 | 释义 | 同义替换 |
| --- | --- | --- | --- | --- | --- | --- |
| `AM-101` | `AT-001` | `chiaroscuro` | 主导 | `tested` 已测试 | 明暗对照：强侧光塑造体积，暗部吃掉一半画面 | `strong side lighting` / `dramatic light shadow` |
| `AM-102` | `AT-002` | `tenebrism` | 主导 | `tested` 已测试 | 极端明暗：光束像刀一样劈下来，暗部几乎全黑 | `dramatic tenebrism` / `single dominant light shaft` |
| `AM-103` | `AT-003` | `rim light` | 辅助 | `tested` 已测试 | 轮廓光：主体背后被光勾出一道边 | `backlit rim` / `edge highlight` |
| `AM-104` | `AT-004` | `single window light` | 主导 | `tested` 已测试 | 单侧窗光：光只从一侧窗口进来，另一侧交给反射 | `window light from left` / `single light source` |
| `AM-105` | `AT-005` | `diffused skylight` | 主导 | `tested` 已测试 | 天顶柔光：天顶罩下来的光，几乎不投影 | `soft overhead light` / `shadowless ambient light` |
| `AM-106` | `AT-006` | `candlelight` | 辅助 | `tested` 已测试 | 烛火：近距离火光，衰减极快，暖到发橙 | `warm candlelit glow` / `oil lamp light` |
| `AM-107` | `AT-007` | `reflected bounce light` | 辅助 | `written` 已编写 | 反跳光：地面或墙反上来的二次光托住暗部 | `bounce fill light` / `indirect reflected light` |
| `AM-108` | `AT-008` | `no cast shadow` | 主导 | `tested` 已测试 | 取消投影：完全取消投影，画面转向平面 | `shadowless flat lighting` / `no cast shadows` |
| `AM-109` | `AT-009` | `dust beam volume` | 辅助 | `written` 已编写 | 可见光柱：光柱成形，悬浮尘埃在光里 | `volumetric god rays` / `visible light shafts with dust` |
| `AM-110` | `AT-010` | `no text or watermark` | 约束 ⚠ | `tested` 已测试 | 禁文字水印：画面里不得出现任何文字、签名、标识、水印 | `no lettering` / `clean image without text` |
| `AM-D10` | `AT-122` | `distant range fading into haze` | 局部 | `tested` 已测试 | 远山没入雾中：最远的一层山只留一条淡影，边界要化开 | `distant mountains fading into mist` / `far range dissolved in haze` |
| `AM-D11` | `AT-123` | `light falling from one side only` | 局部 | `tested` 已测试 | 单侧受光：光只从画面一侧进来，背光面全部沉下去 | `light from a single side` / `one sided illumination` |
| `AM-D12` | `AT-124` | `shadow side merging into ground` | 局部 | `tested` 已测试 | 暗面并入地面：背光区域与地面暗部连成一片，不留交界线 | `shadow side merges into ground tone` / `continuous shadow and ground` |

- **`AM-101` `chiaroscuro`** —— 一旦画面里有第二个光源，这一条立刻失效。
- **`AM-102` `tenebrism`** —— 暗部要真黑，不能靠后期提亮；提亮就等于取消这条。
- **`AM-103` `rim light`** —— 是分离主体与背景最省事的一招，比整体提亮有效。
- **`AM-104` `single window light`** —— 室内题材最稳的默认光；给两个窗就废了。
- **`AM-105` `diffused skylight`** —— 阴天或北向窗的逻辑，画面会平但通透。
- **`AM-106` `candlelight`** —— 光源必须在画面内，否则橙调没有理由。

- **`AM-C03` `square social format`** —— 方形最安全，但也最容易平庸，关键在中心层次。
- **`AM-C04` `editorial full page`** —— 至少留三分之一为空白文字区，否则排版会挤。
- **`AM-C05` `book plate frontispiece`** —— 书页图要考虑与文字并置，密度不宜过满。
- **`AM-C06` `concept art keyframe`** —— 要交代空间关系但不追求气氛模糊。
- **`AM-C07` `canvas print ready`** —— 实体画布常用 2:3、3:2、1:1 与黄金比，不要出屏比。
- **`AM-C08` `decorative panel`** —— 这类图要两面都经得住看，边缘不能草率。
- **`AM-C09` `no watermark no signature`** —— 常驻约束，默认进负面词。
- **`AM-C10` `generous margin`** —— 留边距要显式写出来，模型默认总是铺满。
